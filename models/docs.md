# Аналитический слой интернет-магазина

Витрины по схеме «звезда» в хранилище Greenplum (база `dwh`). Сырые таблицы OLTP-базы
магазина загружает в схему `raw` сервис `loader`, dbt преобразует их в три слоя:

| Слой | Схема в базе | Что внутри |
|---|---|---|
| staging | `analytics_staging` | по одной модели на таблицу источника: переименование, типы, простые флаги |
| intermediate | `analytics_intermediate` | JOIN, агрегации, разворот дерева категорий |
| marts | `analytics_marts` | факты `fct_orders`, `fct_order_items` и измерения `dim_customers`, `dim_products`, `dim_dates` |

Бизнес-вопросы, на которые отвечают витрины: выручка по месяцам и категориям товаров,
доля покупателей по каналам привлечения, средний чек по городам, возвраты по брендам.

**Что нашли тесты.** Тест `assert_confirmed_order_not_overpaid` работает с уровнем
`warn`: по заказу 113 прошли два успешных платежа по 200 рублей при сумме заказа 200.
Это двойное списание в источнике, а не ошибка витрины, поэтому данные не подгонялись:
витрина показывает проблему, а решение принимает платёжная команда.

**Подтверждённая покупка** — заказ со статусом `paid`, по которому прошла хотя бы одна
успешная оплата. Возврат оплатой не считается: в источнике он записан успешной операцией
с отрицательной суммой.

Из определения следуют два случая: заказ со статусом `paid` без платежей
подтверждённым не является (например, заказ 119), а возвращённый заказ не является
подтверждённым, даже если деньги по нему приходили.
